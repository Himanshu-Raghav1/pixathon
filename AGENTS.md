# AGENTS.md — Pixathon

## Mission
Build a complete, playable, polished puzzle game that strictly follows `PROBLEM_STATEMENT.md`.

## Core Rules
- Read `PROBLEM_STATEMENT.md` before implementation. Treat it as the source of truth.
- Start coding quickly. Avoid lengthy plans, unnecessary questions, and excessive explanations.
- Build the smallest complete playable version first; polish it afterward.
- Prioritize correctness, usability, creativity, and a reliable demo over unnecessary complexity.
- Reuse the existing stack, dependencies, components, and working code.
- Do not rewrite working features or add dependencies without a clear reason.
- Keep puzzle logic, level data, and UI reasonably separated.
- Make every visible control functional. Do not leave placeholder interactions.
- Keep the UI responsive, accessible, intuitive, and visually consistent.
- Add features only when they improve the puzzle or satisfy the requirements.

## AI Efficiency
- Work autonomously on clearly specified tasks.
- Break large tasks into small, verifiable milestones.
- Make focused changes instead of repeatedly rebuilding the project.
- Inspect existing code and actual errors before proposing fixes.
- Ask questions only when missing information blocks a correct implementation.
- Do not repeatedly explain plans or duplicate completed work.
- Never claim a feature, test, or deployment works without verification.

## Testing
- Run the application and relevant tests after meaningful changes.
- Verify core interactions, win conditions, restart, and level progression.
- Validate every shipped level for solvability.
- Check browser errors and desktop/mobile layouts.
- Fix critical regressions before adding polish.

## Project Discipline
- Keep `README.md` and `AI_LOG.md` concise and updated with actual information.
- Record important prompts, AI mistakes, corrections, and verification in `AI_LOG.md`.
- Preserve working versions through meaningful Git commits.
- Never expose API keys, credentials, or secrets.

## Final Delivery
- Confirm mandatory requirements are implemented.
- Ensure the game runs and is playable from start to finish.
- Verify the final build and document known limitations honestly.
- Leave the repository ready for submission.

When time is limited, prioritize a correct, complete, playable game over extra features.
